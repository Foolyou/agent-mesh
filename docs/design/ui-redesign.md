# Web 控制台整体重设计 — 设计 Spec

状态：设计（经 brainstorming 与用户逐段确认，2026-06-20）。本文是后续实施各阶段的权威依据。
范围：`src/web/` 桌面端 + 移动端的整体重设计——从"功能堆砌"转向有信息架构、有视觉层级、设备分治的现代控制台。**本文只定方向与决策，不含实现代码。**

---

## 0. 背景与目标

当前 web 控制台功能完整，但呈"专家控制台"式的**信息密度过载 + 信息架构扁平 + 视觉层级弱 + 移动端靠折叠**（详见 `docs/design/ui-redesign-toolkit.md` 的现状评估）。本次重设计的核心**不是换皮**，而是：

- 重排**信息架构（IA）**，建立清晰主次；
- 建立现代**视觉层级**（排版/留白/分组）；
- **设备分治**的真响应式（移动端为触屏重排，而非折叠桌面）；
- 全程守住 **WCAG AA**（复用现有 a11y 门禁）。

**要保留的优点**：信息密集的硬核效率、清晰的 mesh→agent→对话主线、已达标的可访问性。

---

## 1. 锁定决策（逐段经用户确认）

### 1.1 设备定位
- **桌面、移动各走各自合适的交互，不强行一致。**
- 桌面 = 完整能力（多 agent 掌控的主战场）。
- 移动 = **精心裁剪的主线子集**，可缺功能；核心三件套 = **mesh 状态 + mesh 会话 + 审批**，其余皆简化版。

### 1.2 视觉气质
- **转向现代控制台**（与终端 retro 风做干净切割）：去掉全大写标签、去掉等宽满屏、用可读无衬线字体（正常大小写）+ 清晰字号层级 + 卡片/留白/分组建立层级；等宽只留给数据/代码/ID/transcript 代码块。
- 状态用清晰的 chip/色块 + 图标（不再只靠小圆点 + 短词），但保持信息密度。
- **同时把 WCAG 做到足够优秀**（现代调色板必须过 AA）。

### 1.3 信息架构优先级
- 当前优先级 **A（运行态）> C（看板）> B（管理）**。
- 架构上把 **A 与 C 设计成可互换主次的平级骨架**——用户后续可能把 C（看板/项目视角）升为主线，届时只是改默认落点，不需重构。
- **B（管理 / 总控 Mesh Assistant）= 低频次级入口。**

### 1.4 整体结构（方向①：运行态驾驶舱 + 视图切换器）
- **顶栏（全局）**：左=品牌/连接态；中=当前 mesh 选择 + **视图切换器 `[运行态 | 看板]`**；右=全局控件区（🔔 通知中心[未读] · 管理[harness/channel/Assistant] · 主题 · 语言 · 用户/授权）。次要项进"管理/溢出"菜单。
- **左栏**：轻量导航——mesh 列表 + 状态，可折叠；不再塞助手全对话。
- **主舞台（中央，最大）**：随视图切换器显示运行态(A) 或看板(C)；视觉层级与留白主要在此建立。
- **右栏（上下文，按需）**：拓扑/活动/邮件不再平铺四 tab，改为跟随主舞台选中对象**按需展开**，可收起。
- **总控 Assistant** 移出主区，收进顶栏"管理"入口（低频可达，但别藏太深）。

### 1.5 运行态视图（A）
- **拓扑图 = 全局概览层**（"放大拓扑"看全员状态/关系，桌面强项）；点拓扑节点 → **聚焦该 agent 的单条转写**。
- **单聚焦转写**（确认：不做多 agent 同屏并排）+ 底部 composer 发指令；默认聚焦 router。
- **消解"两个聊天入口"混淆**：只有一个聚焦转写区，router 只是拓扑里的第一个 agent；总控 Assistant 进"管理"，不在此争。
- **权限批准就地醒目内联**（批准/拒绝 + 概览红点计数），不再埋。
- **右侧按需上下文**：拓扑/该 agent 的活动·邮件，想看才展开。
- rail 旧四 tab 拆解：board→升 C 视图；activity/mail→按需上下文；history/权限历史→并入通知中心。

### 1.6 看板视图（C）
- 把现挤在 rail 小 tab 的 board **提升为完整平级视图**：list / detail / kanban + router 派活台 + 状态自动回流。日后"C 升主"= 改默认落点。

### 1.7 移动端
- **底部 tab**：`运行态 · 看板 · 更多`（"更多"收纳管理/设置/🔔通知中心）。
- **移动运行态**：用 **agent 卡片列表**（状态 + 待批红点）替代可缩放拓扑（拓扑留桌面强项）→ 点开**单个 agent 聚焦转写 + composer**；**待批权限置顶醒目**。
- **移动看板**：list + detail 为主（kanban 简化或留桌面）。
- 有意砍掉/弱化：可缩放拓扑、深度管理、多窗并排。保住主线：mesh 状态 / mesh 会话 / 审批。

### 1.8 全局通知中心
- **定位**：应用级（跨 mesh）系统消息聚合器，与"对话内容"、"某 mesh 局部事件流"分开。
- **收**：系统/运维类——harness 升级提示、前端自更新、连接/服务状态、系统告警。**不收** transcript、不收 mesh 局部 activity/mail。
- **入口**：顶栏 🔔 带未读计数/红点 → 点开列表/抽屉、可回看历史；移动端在"更多"。
- **未读/已读 + 历史 = 服务端持久化**（跨刷新/跨设备可回看，解决现有 toast 易错过、无历史）。
- **与内联提示主从**：高紧急、需即时阻断的（如必须刷新的前端自更新）保留轻量内联横幅 + 同时归档进中心；非阻断信息优先进中心；同一条系统消息不只存在于易逝内联层。
- **实现锚点**：现有系统消息源已集中在 `store.ts`（`getUpgrade`/`getToasts`）+ `/api/harnesses` 旧版 agent 信息，在其上聚合即可，不新建采集层。

---

## 2. 不变量（每阶段必须保持）
- 不破坏现有 **device-auth 门禁**、**诊断面板（mesh ps/doctor）**、**feishu channel**、p2p→Assistant 等现有功能。
- **WCAG AA 全绿不倒退**：主题由 8 精简为 **3 套（暗 / 亮 / 护眼）**，每套用 a11y 门禁（`contrast.ts` / `a11y-audit.ts` / `a11y.e2e.ts`）守住 AA（文本 4.5 / 大字 3 / 非文本 UI 3:1）。
- 每阶段保留无关用户改动；分 commit；可验收。

## 3. 分阶段实施计划
渐进推进，每阶段过 a11y 门禁、走 mesh 任务流（task/<slug> 分支 + builder + reviewer，prdmgr 集成复跑全量 gate + 截图前后对比）。**不写工时，按 commit/阶段推进。**

1. **阶段1 — IA 骨架 + 视觉 token（地基）**：新外壳/导航（顶栏视图切换器 + 🔔、左轻导航、中央主舞台、右按需上下文）+ 3 套主题 token（暗/亮/护眼，可读字体、字号层级、卡片/留白基元），全过 AA。先线框定稿再落地。
2. **阶段2 — 桌面运行态主视图(A)**：拓扑概览 ⇄ 单聚焦转写 + composer + 就地审批 + 按需上下文。
3. **阶段3 — 看板视图(C)**：升为完整平级视图（list/detail/kanban + 派活台）。
4. **阶段4 — 全局通知中心**：服务端持久化聚合 + 顶栏 🔔 + 内联横幅主从。
5. **阶段5 — 移动端**：底部 tab + 核心三件套（状态/会话/审批）+ 其余简化版。
6. **阶段6 — 管理入口(B) + 组件细化 + 回归固化**：Assistant/harness/channel 收进"管理"；组件态打磨；把"截图回归 + a11y 门禁"固化成本仓 skill。

---

## 4. 成功标准
- 打开即有清晰主次：主舞台聚焦当前任务，新用户知道先看哪。
- 现代可读的视觉层级（去全大写、留白分组、卡片层级），扫读成本显著下降。
- 移动端为触屏重排、主线三件套好用，而非折叠桌面。
- 3 套主题全过 WCAG AA，无回归。
- 全程无现有功能回归（device-auth / 诊断 / feishu / 看板 / p2p 均正常）。
